# Changelog

## 0.8.0 — 2026-11-12

- **Several regions in one run.** `--region a,b,c` or `--all-regions` (the regions `ec2:DescribeRegions` lists as enabled) read each region with the existing collectors, four at a time; a region with nothing in it is left out, and a region that fails is skipped with a warning. Everything merges into one `aws.json` and `ts.json`: every row carries `region`, a name two regions share gets a prefix (`eu-west-1:orders`) with every reference to it, global services (CloudFront, S3, cost) are read once, traffic and errors add up and latency is the worst of any region. Linking, streams, drift and the model match on plain names, and a queue URL in a service's settings means the queue in its own region.
- **Several accounts.** `--profile p1,p2` reads one account per profile. Opt-in `--org-role <RoleName>` lists the organization's accounts (`organizations:ListAccounts`) and assumes that read-only role in each (`sts:AssumeRole`, session `hopscope`, one hour; `--accounts` to limit); an account that can't be read is skipped with a warning. Rows carry `account`: the alias (`iam:ListAccountAliases`) or `acct-••••1234`, never the number. The IAM policy gains `iam:ListAccountAliases` and `ec2:DescribeRegions`; [Getting started](docs/getting-started.md#several-regions-or-accounts) shows the role to create and its trust policy.
- **Console.** Region and account filters on Architecture, Components and All services, where each resource runs on its card and in its drawer, clusters grouped by region in the architecture, and traces drawn in their compute's region.
- **Lambda functions linked to code.** A folder is placed on the functions named exactly after it (plus the shared prefix), or with `lambda:<function>` in `hopscope.json`; a serverless route traces through API Gateway into its function.
- **Ruby.** Rails `config/routes.rb` (resources/resource with only/except/param, nesting, member/collection, namespace/scope, verb routes, `match … via:`, root, `devise_for` sign-in/sign-out/sign-up), Sinatra and Grape route blocks (with Grape `prefix`/`version`). Rails routes point at the controller action. Imports through `require_relative` and Rails autoloading. Externals: ActiveRecord (database from the Gemfile; sqlite3 alone draws none), Redis/`Rails.cache`, AWS SDK (SQS, SES, S3, Step Functions, Kinesis), Kafka, HTTP clients. The `Gemfile` folder is the service. All 19 RealWorld endpoints found on a public Rails sample.
- **PHP.** Laravel route files (verbs, match/any, resource/apiResource with only/except, prefix groups, `/api` for routes/api.php, `[C::class, 'm']` and `'C@m'` targets resolved to the controller method), Symfony `#[Route]`/`@Route` with class prefixes, Slim/Lumen routes and groups. Imports through `use`/namespaces with a composer.json PSR-4 fallback, and literal requires. Externals: Eloquent/DB facade/Doctrine/PDO (database from `config/database.php` or composer.json, never `.env`), Cache/Redis, AWS SDK, Kafka, Guzzle/Http. Config-array files get no externals. The `composer.json` folder is the service. 19 of 19 RealWorld endpoints on a public Laravel sample.
- **Rust.** axum `route`/`nest` (inline, `let`-bound and router fns, also across files), actix-web route/resource/scope and attribute macros, Rocket macros under `mount`. Routes point at the handler fn. Imports through `mod`/`use`/qualified paths. Externals: sqlx/diesel/sea-orm (postgres or mysql), redis, AWS SDK crates, rdkafka, reqwest. The `Cargo.toml` folder is the service; `target/` is skipped. 19 of 19 RealWorld endpoints on public axum and actix-web samples.
- **Call flows for Ruby, PHP and Rust.** A shared tracer (`langs/scriptflow.py`, standard library only) follows a handler one level into the service's own code and records ORM and SQL calls with the model or the table named in the SQL, Redis, AWS SDK, Kafka and HTTP calls, with conditions in words and error handlers marked on-error. A language may point a route at its handler's file and line (Rails and Laravel controllers, Rust handler fns), so call flows start at the handler. Manifests are read only inside the repository.
- **Demos.** [Kestrel Coffee on Kubernetes](https://supreeth-ravi.github.io/hopscope/demo-k8s/) (EKS, two namespaces, an Ingress and autoscaler, a crash-looping workload, a Kafka topic read by a Lambda) and [Kestrel Coffee serverless](https://supreeth-ravi.github.io/hopscope/demo-serverless/) (API Gateway, Lambda, DynamoDB, SQS, Step Functions and EventBridge in two regions), both invented and built by `docs/demo-*/make_*.py`.
- **Changed: same-named production services.** Two production copies of one ECS service name (in two regions, or in two clusters of one region) now both show as `name (cluster)` in the model and console, instead of one hiding the other.
- **Hardening.** AssumeRole passes a read-only inline session policy built from `iam-policy.json`; `--org-role` takes at most one profile; region, role, account and alias values must match exactly (no trailing newline); collector warnings mask account numbers; a region where every collector failed is reported as such, and a run that reads nothing stops with the reasons; hopscope.json keys without a region prefix cover every region's copy; history across a skipped region removes only that region's rows; Lambda name linking needs at least three functions to guess a shared prefix and never places folders named `handler`, `lambda`, `function(s)`, `lib`, `common` or `shared`.
- **Ruby.** Rails concerns (`concern`, `concerns:`), shallow nesting and brace `member { … }`/`collection { … }` blocks; `%w[…]`/`%i(…)` contents never open blocks; Ruby and PHP model checks take one pass per file.

## 0.7.0 — 2026-11-12

- **Kubernetes in design mode.** Plain manifests (Deployment, StatefulSet, DaemonSet, CronJob, Job, Service, Ingress with IngressClass, Gateway API HTTPRoute, ConfigMap env references, HorizontalPodAutoscaler), Kustomize bases and overlays as written (resources, patches, images, replicas, namePrefix/nameSuffix, namespace; no remote bases) and Helm charts without helm (simple `.Values`, `.Release.Name` and `include "x.fullname"` only; a `rendered/` or `manifests/` folder wins). Workloads become service rows per namespace with replicas, images, allowlisted env and ConfigMap refs (never Secrets) and HPA min/max; Services, Ingresses and HTTPRoutes become entries routed by selector. `skaffold.yaml` artifacts tie images to their build folder exactly, then compose builds and Dockerfile folders. Single-replica checks skip jobs, DaemonSets and autoscaled workloads.
- **EKS and live Kubernetes (opt-in).** EKS clusters and node groups in the inventory. `--kube-context <ctx>` / `--kube-contexts a,b` read workloads, services, ingresses, HPAs and warning events with read-only `kubectl get` (list-form, timeout, no shell, never Secrets), mapped like design mode; CrashLoopBackOff, ImagePullBackOff, FailedScheduling and OOMKilled events join the "couldn't start tasks" actions. Event text is never stored: only allowlisted reasons are kept, as fixed descriptions (a probe failure is "readiness probe failed", an image pull keeps only the repository name). kubectl output is capped at 200 MB.
- **Workflows and streams.** Step Functions (the services each definition calls, failed executions), Kinesis Data Streams (incoming records, iterator age), MSK clusters, EventBridge rule targets and Lambda event source mappings. New actions: failed executions, Kinesis readers falling behind, event sources disabled or failing. The IAM policy gains only the read actions these need (`eks:List/Describe*`, `states:ListStateMachines`, `states:DescribeStateMachine`, `kinesis:ListStreams`, `kinesis:DescribeStreamSummary`, `kafka:ListClustersV2`, `events:ListTargetsByRule`, `lambda:ListEventSourceMappings`).
- **Code to streams.** All languages detect Step Functions, Kinesis and Kafka clients; call flows record workflow starts, stream writes (with literal stream names) and Kafka sends (with the topic) in Python, Java, Kotlin and C#. The linker ties code to the streams, state machines and topics it names and lists their Lambda consumers; traces follow them.
- **Observed traffic: browser captures.** `hopscope.py observe --har file.har` matches HAR exports to routes and writes `observed.json` (count, status classes, average time, last seen), keeping only method, path pattern (a segment survives only as a plain lowercase word or a route literal), status and timing; HARs up to 100 MB. Traces say "seen in a browser capture (N requests: …)", a new MCP tool `observed` lists what was seen, and requests no scanned route serves are listed.
- **Console.** Kubernetes namespaces, workloads and entries; a Workflows and streams section; Browser captures with "seen ×N" pills on routes; traces follow stream, workflow and Lambda consumers.
- **Hostile files.** YAML aliases are refused in Kubernetes, Kustomize and Helm files; compose and CloudFormation keep anchors but read only plain values; nesting too deep to parse skips just that file.
- **Disabled event sources** are one action, raised only when messages still arrive at their source.
- **Go: gorilla/mux.** `r.HandleFunc(baseUrl+"/cart", h).Methods(http.MethodPost)` gives one route per method, with a same-file string-constant prefix resolved (otherwise `{?}`).
- **Fix.** Files named in `code.json` (call flows, Java/C# flows, the linker's queue scan, floorplan imports) are read only inside the scanned base, never through a symlink, and within the size limit.

## 0.6.0 — 2026-11-12

- **Language plugins.** Each language the code scanner reads is a module in `scripts/langs/` with a small documented contract (`EXTENSIONS`, `SERVICE_MARKERS`, `routes`, `imports`, `externals`, optional `prepare`, `mounts`, `client_calls` and `flows`); `code_scan.py` is the driver. Python, JavaScript/TypeScript and Go moved there; a golden test pins their output, which is unchanged except where noted below (a UI package's handler-less `api.get('/x')` is a call, Express mounts prefix routes, and symlinked files that lead out of the repository are no longer read). [Development](docs/development.md#adding-a-language) explains how to add one.
- **Java and Kotlin.** Spring Boot / Spring MVC controllers (class and method mappings, `@RequestMapping(method = …)`), Micronaut, JAX-RS and Ktor routing blocks; controllers implementing interfaces generated from an OpenAPI spec take their routes from the spec. Imports resolve through package declarations. Externals: JDBC/JPA/Spring Data (the database from `pom.xml`, Gradle and `application.*` files), Redis, AWS SDK v1/v2 (SQS, SES, S3, Cognito), OpenSearch/Elasticsearch, Kafka (a new external kind) and HTTP clients (`http`, also new). Services are found from `pom.xml`, `build.gradle(.kts)` and `settings.gradle`; `target/` and test classes are skipped.
- **C# / ASP.NET Core.** Attribute-routed controllers with the `[controller]` and `[action]` tokens and routes inherited from a base controller, `[AcceptVerbs]`, and minimal APIs with `MapGroup` prefixes. Imports through namespaces and `using` (including global usings). Externals: EF Core, SqlClient, Npgsql (SQL Server is a new external kind, `mssql`), StackExchange.Redis, AWSSDK (SQS, SES, S3, Cognito), Confluent.Kafka, MassTransit riders and HttpClient. The folder of a `.csproj` is the service; `bin/` and `obj/` are skipped.
- **Call flows for Java, Kotlin and C#.** A brace-matching tracer (no new dependencies) follows a handler's calls through injected fields, parameters and locals into the service's own classes, resolving interfaces to their implementation, and records repository and DbContext calls (with the entity and the statement in JPQL/SQL text), AWS SDK, HTTP, Redis and Kafka calls. Calls under `if`/`else`/`switch`/`when` are conditional and in `catch` on error, with the condition in words, as for Python.
- **Frontend to backend.** HTTP calls in JS/TS frontends (fetch, axios and its instances, Angular `HttpClient`, SWR/`useFetch`) are normalised and matched to backend routes, tolerant of an `/api` or `/api/v1` prefix and of case; code.json gains `clientCalls: [[file, line, method, path, route index or null]]`. In a frontend, `api.get('/x')` is now a call rather than a route. A variable glued to the last segment (`/agents${qs}`) or anything after `?` is a query string and is dropped; axios/ky instances and fetch wrappers (defined in the file or imported from a relative module) prefix their calls with the literal path of their base URL. When no route matches the whole path, the one same-method route whose path ends with the call's (after a plausible prefix such as `/api/v1` or `/<word>`) is matched, marked `"suffix"` as a sixth item of the row.
- **Express mounts.** `app.use('/api/v1', router)` (an imported or required router) prefixes that router's routes, one route per mount when a router is mounted twice. Python keeps its first-mount behaviour.
- **Path constants.** Spring mappings and ASP.NET templates written as constants (`@GetMapping(Paths.CUPS)`, `[HttpGet(Routes.List)]`) resolve through the repository's string constants; one that can't be resolved shows as `{?}` and is never matched to a frontend call. A class-level `@RequestMapping` with several paths gives routes under each. Chained `app.MapGroup("/a").MapGroup("/b").MapGet(...)` and attributes on the same line as the class or method are read.
- **Containment.** Files are read only inside the scanned repositories: symlinks leading out are skipped by the scan, client base URLs are followed only into scanned files, and OpenAPI specs and build files are read only when they are regular files inside the service.
- **Trace starts at the button.** `trace` (CLI, MCP and console) lists the frontend files that call a route (`calledFrom`, "Called from: storefront/src/api.ts:11") and accepts a frontend file or `file:line` to trace the route it calls.
- **Drift.** A frontend call that no backend route serves is a finding ("Frontend calls GET /api/x, which no backend route serves") when the scan has backend routes and at least one call matched; otherwise (for example a frontend scanned alone) the calls are listed as uncertain. At most 50 such findings, then one row counting the rest.
- **Console.** Draws SQL Server, Kafka and HTTP APIs as external systems and SQL Server as a database; shows who calls a traced route; finds routes by frontend file name.

## 0.5.1 — 2026-11-12

- **Unconfirmed links are no longer shown as fact.** Links below 0.6 confidence (the ones `hopscope.py review` lists) are marked wherever Hopscope says which compute runs which code: `trace`, `impact`, `what_runs`, `health` and `resources` return them as `{"name", "confidence", "unconfirmed": true}` with a note to confirm them (confirmed links keep their shape), the command line prints "analytics-engine (unconfirmed link, 0.5 — confirm with hopscope.py review)", drift findings that rest on a link carry `linkConfidence`, the MCP tool descriptions tell agents to call them unconfirmed, and the console drawer, module view, trace brief and drift list say so.
- **Design-mode drift wording.** A container setting naming a queue or database that isn't in the files now says it may be defined in another repo or created outside infrastructure files. When a scanned file names the resource, the finding is informational and no longer counts as a broken setting in the action queue. Likewise a queue the code names that the files don't define is informational in design mode: it may be defined in another repo or created at runtime. Live mode is unchanged.
- **Hardening.** Snapshot copies (`aws.json`, `links.json`, `model.json`) and each snapshot's `diff.json` are masked for account numbers before they are written. The drift check reads only code files that resolve under the scanned repo, and never through a symlink.
- **Console.** Drift badges such as "LINK MAY BE WRONG" stay on one line; the title wraps instead.

## 0.5.0 — 2026-11-12

- **Snapshots and changes.** Every `all`, `collect` and `design` run copies `aws.json`, `links.json` and `model.json` into `<workdir>/snapshots/<UTC time>/` (with hashes and counts for `code.json` and `flows.json`) and writes `changes.json`: resources added, removed or changed (counts, sizes, images, task-definition revision, load balancer rules, queues, databases), links that moved, and actions that appeared or resolved. The last 30 are kept (`--keep`). `hopscope.py changes [--since <snapshot>]` prints them.
- **Deploy history.** In live mode each ECS service records its task-definition revision and when it was registered, its current deployments, up to five earlier revisions and the last 20 service events other than "steady state" (those are counted), with ARNs reduced to names and account numbers, endpoints, IP addresses and EC2 host names masked. The IAM policy adds `ecs:ListTaskDefinitions` (read-only) for the earlier revisions; without it the current one is still recorded.
- **Drift report.** `drift.json` and `hopscope.py drift` compare the code, the infrastructure files (now also read in live mode, into `iac.json`) and live AWS: resources in AWS but in no file, files never deployed, desired counts, images and task-definition families that differ, queues no code references, queues the code names that don't exist, settings pointing at missing queues or databases, and links that may be wrong (a file row with the service's name builds another folder). AWS and file rows match only on the same name apart from environment words and numbers, a variable prefix, or the same code folder; names that merely share words never produce a finding. Per-tenant queue families are one finding each (referenced when the code contains their static prefix), with counts. Design mode runs the code-to-files checks only.
- **Actions.** The action queue gains up to three drift items with grouped counts, one for a deploy (or new revision) in the three hours before 5xx jumped, and up to three for services whose tasks couldn't start in the last 72 hours (placement, image pull or health-check failures).
- **Console.** A Timeline tab: deploys and builds on one 72-hour axis next to hourly 5xx, with what changed on click; a Drift list on the Timeline and in the Components view. Design mode lists builds and drift with no time axis.
- **MCP.** Two more read-only tools: `changes` and `drift`.
- The Kestrel demo has deploys (shop-api revision 42 shortly before the Sunday checkout outage), three builds and a drifted Terraform file.

## 0.4.1 — 2026-11-12

Fixes from running design mode on a large monorepo:

- **No account numbers in the output.** Design rows keep only an image's repository name (whether it is your own image is still decided from the full reference), the infrastructure scan stars out every standalone 12-digit number (keys included), and link evidence is masked the same way. Longer digit runs, such as epoch suffixes in queue names, are left alone so the names still match the code.
- **Compose build folders.** A `dockerfile:` in a folder below the build context (context at the repo root, `dockerfile: admin/Dockerfile`) now places the service on that folder. Contexts outside the repo are still rejected.
- **Folders with no code stay unplaced.** A service built from a folder that holds no scanned code (SQL, dbt, config) is no longer guessed onto another service by name; links.json records why under `unplacedWhy` and the design checks list it separately.
- **Compose variants.** `docker-compose.<variant>.yml` maps to its own cluster (`<folder>-<variant>`, `compose-<variant>` at the root) and staging/dev/test variants count as staging. Service keys are guaranteed unique across files.
- **`env_file:` is read.** Paths, lists and the `{path, required}` form, next to the compose file and only inside the repo, 500 lines per file. Inline `environment` wins, and every value still goes through the same allowlist, so no credentials are kept; plain host names under `*_HOST` keys are kept, as for inline values.
- **Same-named data stores.** A second `postgres` or `redis` from another compose file shows as `redis (<cluster>)`; its endpoint stays the bare service name and database links prefer the store from the service's own file.
- **hopscope.json folders resolve.** Placement, label and queue entries written for a parent folder (`<repo>/payments`) match the scanned service (`payments`). An entry that matches no scanned folder is not used; a placement goes to review with the reason, and each one is reported as a warning.
- **Linker crash.** An environment value holding only an SQS host (no queue name) no longer stops the linker.
- **Plain-word route queries.** `hopscope.py query checkout`, `find_routes` and the MCP `trace` tool match words against the method, path segments and title; a clearly best route is traced, otherwise the close candidates are listed.

## 0.4.0 — 2026-11-12

- **MCP server.** `hopscope_mcp.py` gives agents seven read-only tools over a build: `find_routes`, `trace`, `who_calls`, `what_runs`, `impact`, `resources` and `health`. Standard-library Python over stdio (MCP 2025-06-18, older 2025-03-26 and 2024-11-05 clients accepted). The Claude Code plugin registers it for `<project>/.hopscope`; Codex users add it with `codex mcp add` (see docs/codex.md).
- **Change impact.** `hopscope.py impact <file>`: the files that depend on it, the routes whose handler or code path reaches it (nearest first), the services they run on, and the queues and workers downstream.
- **Route answers on the command line.** `hopscope.py query "POST /orders"` prints the load balancer rule, compute, code path with conditions, queues, workers and database.
- **Exports.** `hopscope.py export --format mermaid|drawio [--route …] --out FILE`: a Mermaid architecture flowchart, a Mermaid sequence diagram of one route, or a draw.io file of the architecture with AWS icons. Labels are escaped.

## 0.3.0 — 2026-11-12

- **Design mode.** `hopscope.py design --repo <path>` builds the console from your code and your docker compose, Terraform and CloudFormation/SAM files, with no AWS account or credentials. The Architecture, Components and Trace views work; there are no live numbers and the Cost tab is hidden.
- **Exact links.** A compose `build:` folder places a service on its code with full confidence. In design mode a queue links to code only through a real reference (a quoted name, a queue URL, or a `...QUEUE` environment variable), not a substring.
- **Environment-value filter.** Values read from infrastructure files are allowlisted: queue names, masked hosts and service names are kept; credential-like values are dropped. Engine and size labels are sanitised, and the console escapes everything read from files.
- **Design checks.** Routes with nothing serving them, queues with no dead-letter queue, production services planned with one task, and services with no code found.
- **Console design view.** "Design" status, planned task counts instead of CPU and memory, skipped files noted in the footer, no DNS box, no Cost tab.
- New dependency: PyYAML.

## 0.2.0 — 2026-11-02

- **Codex support.** Install from the Codex plugin marketplace (`codex plugin marketplace add supreeth-ravi/hopscope`) and ask for a Hopscope console or type `$hopscope`.
- **Analyst and Ask in the local console.** `hopscope.py serve` answers the console's questions with the Claude Code or Codex CLI on your own sign-in: tools, shell and plugins off, an empty temporary folder, no AWS credentials, nothing saved to history. `--engine claude|codex` and `--model` choose. The endpoint answers only same-origin requests carrying a per-run token.

## 0.1.0 — 2026-11-02

First release.

- **Overview**: health status, traffic / errors / latency / saturation for 72 hours, and an action queue with concrete fixes.
- **Architecture**: system-design diagram of what is deployed, wired from load balancer rules and code dependencies.
- **AWS components**: inventory of load balancers, Lambda, SQS, SNS, ElastiCache, OpenSearch, S3, Cognito, SES, ECR and more, with usage.
- **Trace**: any API played hop by hop from DNS through the load balancer rule, container and code path to data stores, queues and workers; conditional steps explain when they run; voice narration.
- **Cost**: 30-day spend by service and savings that don't touch production.
- Code map from the built-in scanner (Python, JavaScript/TypeScript, Go) or an existing floorplan map.
- Linker with confidence, evidence and a review list; `hopscope.json` for corrections.
- Read-only collectors; secrets dropped, account numbers masked; local server answers only on localhost.
